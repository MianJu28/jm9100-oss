# 火狐硬件 WebRender 渲染排查（2026-11-02）

目标：查清"火狐走我们的驱动时，WebRender 只画出页面底色、所有图元（色块/文字/渐变）不可见"的根因。
相关遗留目标：用户 m10181（"一半黑一半白"）、m09976（"按正路走"）、m11299（"继续追查"）。

## 0. 本轮先修了测量方法（关键）

**此前若干次火狐测量是不可信的**：测试 profile `/tmp/ffhw2` 后来会弹出一个 402x174 的对话框窗口
（不再是页面窗口），而我的直方图一律裁剪固定矩形 `crop=1070:822:265:43`
（按窗口早期位置定的），于是**可能一直在量用户自己的火狐窗口或残留窗口**。

现在改为可靠的测量装置 `reports/evidence-ffrender/ffshot.sh`：
1. 每次用**全新 profile**（`/tmp/ffp3`，含 `gfx.webrender.all=true`、`software=false`、
   `gfx.x11-egl.force-enabled=true`、`browser.aboutwelcome.enabled=false` 等）；
2. 起完火狐后用自写 `findwin2`（XQueryTree 递归 + `_NET_WM_NAME`/`WM_NAME`）**按标题 "DIAG" 取窗口几何**，
   再按该几何精确裁剪 + 7 桶直方图；
3. 只杀"本次新增"的 firefox PID（避免误杀用户进程）。

## 2. 驱动侧取证：把渲染目标内容 dump 出来

在 `src/mwv207-umd/drivers/mwv207/mwv207_draw.c` 的 `mwv207_draw_vbo()` 末尾加了取证钩子
（`MWV207_DBG_DUMPWIN=1`，用 winsys 的 `bo_wait` + `bo_map`，与 `mwv207_query.c` 同一安全范式；
**不要**在回调里调 gallium 的 `texture_map`/`buffer_map`，会 SIGSEGV——此前踩过）。
钩子按 `t-<w>x<h>-f<fmt>.raw` **覆盖写**，于是每个目标留下的是**本帧最后一次写入后的内容**。

帧末各目标内容（本次运行，页面＝`/tmp/diagpage.html`：绿底 + 4 个色块 + 两行文字 + 渐变条）：

| 目标 | 格式 | 内容 |
|---|---|---|
| **窗口目标 1280x929** | fmt 54（BGRA8） | 绿 #208020 铺满，**唯独图元所在区域是 (0,0,0,0) 全透明** |
| 页面合成目标 1024x512 | fmt 53（RGBA8） | **100% 全透明黑**（524288/524288 像素为 0） |
| 裁剪掩码图集 1024x1024 | fmt 49（R8） | 63.1% 非零（值 255/240/217/102/227…）✔ 有内容 |
| gpu cache 2048x2048 | fmt 49（R8） | 97.9% 非零 ✔ 有内容 |
| 纹理图集 2048x2048 | fmt 53（RGBA8） | 有内容（白 157099、蓝 89、黄 32、红 2…）✔ |
| 图元头 1024x20 | fmt 16（RGBA32F） | 8.2% 非零（1.0/16.0/32.0/-1.0…）✔ 有数据 |

**判读**：
- 窗口缓冲区的内容**与屏幕所见完全一致**（`windownsv-target-BGRA8.png` 就是"顶部黑带 + 大片绿"）
  → **呈现/合成那一环没问题**，问题在"图元根本没画出来"；
- 而图元该占的像素是**全透明**，不是错色 → 图元的片元输出 alpha=0（或几何退化）→ 被合成成黑；
- 底色绿色来自 WebRender 的 **scissored clear**（清屏）✔，所以"清屏能画、图元画不出"。

## 3. WebRender 本身能用我们的驱动画东西

开 `gfx.webrender.debug.render-targets/texture-cache/profiler` 后，屏幕上出现了
红/蓝/黄/绿等调试覆盖层像素（`shot-dbg.png`：蓝 7.1%、红 4.6%、绿 0.9%、黄 0.3%）
→ **绘制路径、着色器、纹理取样都不是"完全不能用"**，故障特定于**页面图元**这条路径。

## 4. 用新装置重做的 pass 二分（旧结论不可信，已重测）

## 5. 当前最强假设

页面图元（`brush_solid` / `ps_text_run` / `cs_*` 系列）与调试覆盖层的差别在于：
前者要**按图元索引从 `sGpuCache` / `sPrimitiveHeadersF` / `sPrimitiveHeadersI`（含 `isampler2D`）取数据**
（着色器里几乎全是 `texelFetch(sGpuCache, address, 0)`），后者用常量。
所以最可疑的是"**图元参数取回来是 0**"：几何退化成零面积、或颜色/mask 为 0 → 全透明。

已排除（探针级、两驱动逐条一致）：`texelFetch` 动态地址（浮点/整型、VS/FS）、矩形纹理取样
（坐标不该缩放，已修）、`UNPACK_ROW_LENGTH/SKIP_*`、浮点/半浮点与 PBO 上传、整型属性→整型 flat varying、
`gl_FragCoord`/导数/`round`/`mod`/`while`/`switch`/`isampler2D`、模板/MRT、大尺寸回读、
顶点属性类型/实例化/VAO、混合、深度/模板、24 位 EGL-X11 呈现（自测通过）。

## 6. 下一步（按性价比排序）

1. **复现单个真实 WebRender 着色器对**：从 `/tmp/glsl-*.log` 取 `brush_solid ALPHA_PASS`（VS obj 96 / FS obj 97）
   或 `ps_text_run`，在独立 ES 3.0 探针里喂合成数据（gpu cache / 图元头 / 掩码），看我们驱动是否输出颜色；
   同一探针在 llvmpipe 上跑作为对照。
2. **dump 页面图元的顶点/实例数据**：用 winsys `bo_map`（不能用 gallium `buffer_map`，会崩）
   在 `draw_vbo` 里读 `pipe_vertex_buffer` 的内容，确认实例属性（矩形几何/颜色）是否真在缓冲里。
3. **盯 32 位窗口表面**：火狐窗口是 `depth=32 visual=0x7d`，而探针实测我们的 EGL
   **无法为 depth 32 的 visual 建窗口表面**（`eglCreateWindowSurface` → `0x3003` EGL_BAD_ALLOC），
   depth 24 正常（品红自测通过）。需要弄清火狐到底把表面建在哪个窗口上，以及
   "图元区域 alpha=0 → 显示为黑"是否与此相关。
4. 若 1/2 定位到具体取样/上传语义，再回头改驱动并出载荷（当前已装栈是 r7，`payload-30`）。
